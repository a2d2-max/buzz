# 허들 회의록 작업기 (2단계)

릴레이 녹음기(1단계, `docs/huddle-recording.md`)가 남긴 녹음을 읽어서
**누가·언제·무슨 말을 했는지 적힌 한국어 스크립트**와 **재생용 섞은 오디오**를 만들고,
요약을 붙여 노션 회의록 DB에 올리는 일을 한다.

진행 기록과 결정 사항은 노션 작업 페이지 "허들 (한국어 및 tiro 기능 구현)"에 있다.

## 정해진 것

- 받아쓰기 엔진은 **Google Speech-to-Text v2 Chirp 3**(`chirp_3`, 지역 `us`, 언어 `ko-KR`).
  FLEURS 한국어 30개 비교에서 CER 4.57%로 가장 좋았다(Qwen3-ASR 7.12%, SenseVoice 9.00%).
  데이터 로깅 옵션은 켜지 않는다. 단가는 분당 0.016달러, 요청마다 1초 올림.
- 트랙(기기)마다 따로 받아 적되, **트랙 안 화자 나누기**를 한다(10/12, "화자 분리가 핵심").
  회의실에서는 마이크 하나만 켜고 2~5명이 말하는 것이 기본이다. 자기 기기로 혼자 말한 트랙은
  예전처럼 화자 = 그 트랙 pubkey. 자세한 것은 아래 "화자 나누기와 누가 누군지".
- 시각은 녹음의 `t_ms`(릴레이가 받은 시각) 기준. 소리 헤더의 `ts_48k`는 시각 맞추기에 쓰지 않는다.
- 녹음 원본과 섞은 오디오는 녹음 버킷 `gs://a2d2-huddle-recordings`(15일 삭제)에만 둔다.
  **스크립트 JSON은 이 버킷에 두지 않는다**(15일 뒤 같이 지워지므로).
- 스크립트와 받아쓰기 장부는 분 버킷 `gs://a2d2-huddle-minutes`(서울, 공개 차단, 버킷 단위 권한)에 둔다.
  `ledger/` 아래만 30일 뒤 지워지고, 소프트 삭제는 7일이다.
- 요약은 Gemini(Vertex AI global). 요약·노션 쓰기는 따로 맡는다.
- 노션 회의록 DB "허들 회의록"에 회의마다 페이지 하나. 녹음 파일은 노션에 올리지 않고 링크만.

## 형태

- Rust 크레이트 `crates/buzz-huddle-minutes`(라이브러리 + 실행 파일). 녹음 읽기는 `buzz-huddle-recording`을 그대로 쓴다.
- 서버에서는 GCP에서 돈다(예: Cloud Run 작업). 인증은 서비스 계정. 개발 맥에서는 `gcloud auth print-access-token`.
- 구글 인증과 GCS 클라이언트는 녹음기와 같이 쓰는 `crates/buzz-gcp` 한 곳에만 있다
  (토큰: 메타데이터 서버·gcloud·환경 변수 `BUZZ_GCP_ACCESS_TOKEN`; GCS: 목록·읽기·앞부분 읽기·쓰기·조건부 쓰기·지우기).

## 하는 일 (순서)

1. **회의 모으기**: 같은 `channel_id`의 세션들을 `started_at` 순으로 모은다(메시 주인 변경·롤링 배포·6시간 넘김으로 나뉜 세션).
   회의 끝 판단(첫판): 마지막 `manifest.json` 뒤로 10분 동안 같은 `channel_id`에 새 세션이 없으면 끝난 것으로 본다.
   `manifest.json` 없이 조각만 있고 마지막 조각 뒤로 10분이 지났으면 조각만으로 마무리한다.
   녹음기는 사람이 방에 있는 동안 모두 음소거여도 30초마다 명단만 든 "살아 있음 조각"을 쓰므로, 이 10분 규칙은 음소거 중인 회의를 끝난 것으로 오해하지 않는다.
   두 단계로 읽는다. 먼저 목록과 세션마다 manifest(또는 조각 머리 36바이트와 마지막 조각 앞 4KiB, Range 읽기)만 읽어
   회의를 나눈다. 조각 본문은 처리할 회의를 잡은 뒤 그 회의 것만 받는다(채널 15일치를 한꺼번에 받지 않는다).
2. **사람별 소리 복원**: 프레임을 `t_ms` 위치에 놓고 Opus(48kHz mono)를 푼다. 빈 곳은 무음으로 채운다.
   같은 사람이 여러 세션·여러 입장에 걸쳐 있으면 회의 시간축 하나로 합친다.
   v2 헤더의 `flags` DTX 비트와 `level`은 말 구간 찾기의 힌트로만 쓴다.
   `seq`가 6프레임 이상 빠지면(5프레임까지는 Opus 감추기) 침묵으로 채우되, 블록 기준 시각(그 블록에서 가장 덜 늦게 온 프레임으로 잡은 시각)부터
   실제로 흐른 시간보다 길게 채우지 않는다. 바로 앞 프레임이 몰려서 늦게 왔어도 기준은 블록이라 덜 채우지 않는다.
3. **말 구간 자르기**: 사람별 소리에서 VAD로 말 덩어리를 찾는다. 덩어리마다 회의 시간축의 시작·끝 시각을 갖는다.
   `--vad-level on`(`BUZZ_MINUTES_VAD_LEVEL`, 기본 off)이면 VAD 는 크기 맞춘 사본을 듣는다(아래 "VAD 크기 맞춤").
   그다음 **화자 나누기**(아래 "화자 나누기와 누가 누군지")가 트랙 안 화자를 찾는다. 여럿이 쓰는 트랙의 덩어리는
   `--room-pieces`(`BUZZ_MINUTES_ROOM_PIECES`)에 따라 보낸다: **cut(기본, A 방식)** 은 화자가 바뀌는 자리에서
   잘라 토막마다 보내고, **whole(C 방식)** 은 자르지 않고 보낸 뒤 단어 시각으로 줄을 화자마다 나눈다. 다른 트랙에서
   새어 든 소리(에코)는 받아쓰기에 보내지 않는다.
4. **받아쓰기**: Chirp 3에 **말 덩어리마다 Recognize**로 보낸다(10/12 긴 트랙 비교로 정함).
   - 요청: `https://us-speech.googleapis.com/v2/projects/{프로젝트}/locations/us/recognizers/_:recognize`,
     `model=chirp_3`, `languageCodes=["ko-KR"]`, 소리는 WAV 머리 없이 LINEAR16 16kHz mono(`explicitDecodingConfig`),
     자동 문장부호 켬. 데이터 로깅 값은 넣지 않는다. 개발 맥 gcloud 로그인으로 부를 때는 `x-goog-user-project`로 과금 프로젝트를 붙인다.
   - 동시에 4개까지 보낸다. 결과가 오는 대로 장부에 적는다. 인증·한도 오류가 오면 새로 보내지 않고, 답이 안 온 요청은 버린다.
   - HTTP 429는 응답의 `ErrorInfo.reason`으로 가른다: `RATE_LIMIT_EXCEEDED`이고 분당(또는 이름 없는) 한도면 요청 제한,
     하루 한도이거나 다른 이유면 한도 다 씀. 이유가 아예 없으면 요청 제한으로 본다(실패한 요청은 돈이 안 든다).
     400 `INVALID_ARGUMENT`는 소리 거절, 401·403·`NOT_FOUND`·`FAILED_PRECONDITION`은 인증·설정 문제로 멈춤, 그 밖은 일시 오류.
   - 덩어리는 VAD가 찾은 자연스러운 말 단위 그대로 보낸다. **쉼을 건너 여러 덩어리를 합치지 않는다.**
     합친 조각에서 Chirp 3가 뒷부분 말을 버렸다(4.5초 쉼을 사이에 둔 조각에서 문장 하나를 통째로 놓침).
   - 덩어리 하나가 너무 길면(Recognize 한도 1분 미만, 기준 30초) 가장 긴 쉼에서 자른다.
   - 덩어리 앞뒤 여유(예: 0.2초)를 붙여 보내고, 스크립트 시각에는 여유를 뺀 말 시작 시각을 쓴다.
   - **단어 시각(`enableWordTimeOffsets`)은 `--room-pieces whole` 의 여럿 트랙 덩어리에만 묻는다.** 켜면 받아쓰기가
     조금 나빠진다(KconfSpeech 같은 덩어리 159개, 실제 Chirp: CER 6.47% → 7.30%, 6,550자 중 +54자, 95% 구간
     +0.35~+1.28%p, 묶음 103개 중 나빠짐 29·좋아짐 9). 그래서 cut(기본)·한 사람 트랙·화자 분리 꺼짐에서는 요청
     본문이 예전과 같다.
     단어 시각은 보낸 소리 시작부터의 ms 로 장부에도 적고(`words`), 다시 쓸 때는 다시 묻지 않는다. 장부의 결과가
     단어 시각을 물은 것인지가 지금과 다르면(화자 분리나 cut/whole 을 바꿈) 그 덩어리만 다시 보낸다 — 단어 시각을
     물으면 글이 달라져서, 같은 설정이면 늘 같은 글이 나오게. 시각을 못 읽으면 글은 살리고 단어 없이 둔다(덩어리가
     통째로 말이 가장 많은 화자에게 간다).
   - 근거(FLEURS 문장으로 만든 4분짜리 사람 트랙 2개, 20문장): 말 덩어리마다 CER 6.98%·놓친 문장 0·시각 오차 중앙값 0.20초·매긴 215초,
     BatchRecognize CER 7.47%·놓친 문장 0이지만 시각이 없거나(단어 시각 끔) 침묵 뒤 첫 단어가 최대 33.9초 일찍 찍힘(켬)·매긴 496초(침묵까지 매김).
   - 실제 대화(짧은 쉼, 겹쳐 말하기)로 다시 재서 확인한다.
   - **같은 덩어리에 돈을 두 번 내지 않는다.** 덩어리마다 결과(받아쓴 글, 또는 "소리 거절")를 회의별 장부에 바로 적는다.
     로컬 폴더면 `<첫 세션 id>.stt.jsonl`(스크립트와 같은 곳, 0600)에 한 줄씩 덧붙이고,
     분 버킷이면 `ledger/{community}/{channel}/{첫 세션 id}/` 아래에 덩어리마다 작은 객체 하나로 쓴다:
     `pieces/{열쇠}`(장부 한 줄), 실행이 끝나면 `bundles/{n}.jsonl`(그때까지의 결과 전부)과 `runs/{n}`.
     분 버킷의 장부 객체는 `ifGenerationMatch=0`으로만 써서 절대 덮어쓰지 않는다(같은 덩어리가 두 번 오면 먼저 쓴 답이 남는다).
     다음 실행은 가장 최근 묶음 하나와 그 뒤에 생긴 조각만 읽는다. 열쇠 자체가 sha256이라 객체 이름에 pubkey가 드러나지 않는다.
     스크립트는 같은 버킷 `transcripts/{community}/{channel}/{첫 세션 id}.json`에 둔다.
     다시 실행하면 장부에 있는 덩어리는 보내지 않는다. 인증 오류로 중간에 멈춰도 그때까지 받은 결과는 장부에 남는다.
     - 열쇠(sha256)는 설정 버전 + 화자 + 보낸 소리의 시각 + **그 구간에 녹음된 Opus 프레임 원본 바이트**로 만든다.
       풀어 낸 소리가 아니라 녹음된 바이트라서, **자른 경계가 같으면** CPU·Opus·리샘플러가 달라도 같은 열쇠가 나온다.
       경계는 풀어 낸 소리에 VAD를 돌려 정하므로, 디코더가 바뀌어 경계가 움직이면 열쇠도 바뀌고 그 덩어리는 새로 보낸다.
       설정 버전에는 덩어리 자르기·VAD 설정, Silero 모델 sha256, 받아쓰기 엔진·지역·언어가 들어가서, 이것들이 바뀌면 모든 덩어리를 새로 보낸다.
       `process`는 시작할 때 Silero 모델 sha256을 확인하고, 다르면 멈춘다.
     - 장부를 열지 못하면 그 회의는 보내기 전에 실패로 끝낸다(장부 없이 보내면 돈을 두 번 낼 수 있다). 다른 회의는 계속한다.
       읽지 못한 줄(쓰다 죽어 반쯤 남은 줄)은 건너뛰고, 개수를 실행 보고와 로그(`unreadable ledger lines`)에 남긴다.
   - 오류 종류마다 다르게 한다.
     - 소리 거절: 다시 해도 안 되므로 바로 "받아쓰기 실패"로 확정하고 장부에 적는다. 회의를 미루는 까닭으로 세지 않는다.
     - 일시 오류: 덩어리마다 3번 다시 시도한다(0.5·1·2초). 분당 요청 제한(HTTP 429)도 이것으로 보되 더 길게 기다린다(5·10·20초).
     - 인증·권한 오류와 "프로젝트 한도를 다 씀"처럼 분명한 한도 오류: 그 회의를 바로 멈추고 남은 회의도 멈춘다(0이 아닌 값으로 끝냄).
   - 다시 시도하고도 일시 오류로 실패한 덩어리가 있을 때만 회의를 쓰지 않고 다음 실행으로 미룬다. 다음 실행은 그 덩어리만 보낸다.
     회의마다 실행은 3번까지다. 3번째 실행에서도 남으면 "받아쓰기 실패"를 단 채로 쓰고, 개수는 `losses.failed_segments`에 남는다.
     실행 횟수는 **받아쓰기를 끝까지 돈 실행만** 센다. 인증·한도 오류로 멈춘 실행, 중간에 죽은 실행, 받아쓰기 전에 실패한 실행은 세지 않는다.
5. **스크립트 만들기**: 덩어리를 시작 시각 순으로 늘어놓아 `huddle-transcript/2` JSON을 만든다.
   회의실 트랙의 화자에는 "회의실 화자 N" 이름표를 붙이고, 목소리가 맞는 사람이 있으면 그 pubkey 를 붙인다.
6. **섞은 오디오**: 모든 사람 소리를 같은 시간축에 섞어 재생용 파일 하나를 만든다. a2d2 데스크톱 앱(macOS WKWebView)의 `<audio>`로 틀 수 있는 형식이어야 한다.
   녹음 버킷 `{prefix}/{community}/{channel}/mixed/{첫 세션 id}.wav`에 **없을 때만** 쓴다(작업기 계정에 덮어쓰기·지우기 권한이 필요 없게).
   이미 있으면 같은 바이트인지 비교한다. 같으면 그대로 쓰고, 다르면(코드가 바뀐 뒤 다시 만든 경우) 있는 파일을 그대로 두고 개수를 남긴다.
7. **요약**(뒤에 붙임): LLM으로 요약·결정사항·할 일(담당자)·주제별 정리.
   할 일은 글뿐 아니라 **구조화된 목록**으로도 낸다. 노션 기획 "노션<>허들 기반 업무 자동화" 1단계(허들 → task 생성)가 이걸 그대로 받는다.
   항목마다: 할 일 내용, 담당자 pubkey(말로 정해졌으면), 기한(말로 정해졌으면, KST), **확정/애매** 구분(담당자나 기한이 불분명하면 애매),
   근거가 된 스크립트 구간(`start_ms`). 회의 주최자는 부모 채널 48100에 서명한 사람으로 정한다. AI가 기한을 지어내지 않는다.
8. **노션 페이지**(뒤에 붙임): "허들 ID"로 같은 회의를 두 번 만들지 않는다.
9. **이어서 하기**: `process`는 스크립트를 쓴 다음, 회의를 잡은 채로 후보정 → 요약 → 노션 페이지로 이어 간다(`--correct on`, `--summary on`, `--notion on`; 기본은 다 꺼짐). 후보정은 아래 "문맥 후보정" 절에 있다.
   - 무엇을 했는지는 **그 스크립트 바이트의 sha256**에 묶는다. 스크립트를 다시 쓰면(`--overwrite`) sha256이 바뀌니, 옛 요약·옛 페이지가 새 스크립트에 붙지 않고 요약과 노션 페이지를 다시 한다.
   - 요약 결과(`huddle-summary/1`)는 스크립트 옆 `{첫 세션 id}.summary.json`(분 버킷이면 `transcripts/…/`)에 `script_sha256`과 같이 둔다. 지금 스크립트 것이 있으면 다시 부르지 않는다(돈을 두 번 내지 않게). 그 파일을 못 읽으면 실패로 두고 Gemini는 안 부른다.
   - 요약·노션이 실패하면 어떻게 세고, 언제 다시 하고, 언제 포기하는지는 아래 "실패 처리" 절에 표로 있다.
   - 노션 기록(`{첫 세션 id}.notion.json`)에는 page id, "끝까지 썼나"(`done`), 스크립트 sha256, 요약 sha256(요약 포기면 `failed`, 요약을 끄고 썼으면 비움)을 적는다. 성공했을 때만 `done`이고, 스크립트나 (요약을 켰을 때) 요약이 다르면 페이지를 다시 쓴다. 그래서 요약을 나중에 켜도 페이지에 올라간다.
   - 기록을 먼저 보고, 할 게 남았을 때만 스크립트를 읽는다(다 끝난 회의는 스크립트를 안 받는다).
   - 요약·요약 실패 횟수·노션 기록을 쓰기 직전에 아직 회의를 잡고 있는지(lease generation) 본다. 놓쳤으면 아무것도 안 쓰고 그 회의를 실패로 센다.
   - 요약·노션이 실패해도 스크립트와 받아쓰기 보고는 남는다. 다음 실행은 빠진 것만 한다. 요약을 켰는데 실패했으면 노션은 그다음 실행까지 기다린다. 작업기 저장소(분 버킷)가 실패하면 그 회의를 실패로 센다.
   - 실행의 시간 상한까지 **10분**이 안 남았으면 요약·노션을 새로 시작하지 않고 다음 실행에 넘긴다. Gemini 에도 그 마감을 넘겨서, 마감 뒤에 끝날 요청이나 기다림은 하지 않는다(요청을 못 보냈으면 다음 실행, 못 기다렸으면 그 실패로 끝).
   - 작업기 안에서 Gemini 요청 하나의 시간 상한은 **540초**다. 출력 상한 32,768토큰이 초당 61토큰 이상이면 다 나오고, 10분 남김 안에서 시작할 수 있는 길이다(10분보다 짧은지는 컴파일 때 검사한다). 2026-10-12 실측(KconfSpeech 58.4분 회의 라벨, 300줄·화자 10명): 입력 21,676·출력 998·생각 0토큰, 한 번에 12.2초, 0.040달러. 출력만 따지면 초당 약 82토큰(입력 처리 시간이 들어가서 실제보다 낮게 잡힌 값)이라, 32,768토큰이면 약 400초로 540초 안에 든다. 출력 상한 32,768은 스키마 상한(결정 30·주제 15×내용 8)과 할 일 40개로 어림한 최대 약 14,400토큰의 2배쯤이라 그대로 둔다. 요약 줄에 걸린 초를 찍으니 실제 회의에서 계속 확인한다. `Retry-After` 는 작업기에서 Gemini·노션 모두 60초까지만 따른다(명령 `summarize`·`publish-notion` 은 300초). 다시 하기 횟수는 그대로다.
   - 노션이 실패하면 페이지는 "실패"로 표시되고(못 하면 `notion-stale`로 찾는다), 실패는 종료 코드 1로 알린다. 로그에는 종류·HTTP 상태·노션 오류 코드만 남긴다(노션 메시지는 페이지 글을 옮겨 올 수 있어서 안 찍는다).
   - 이 바꿈 전에 쓴 요약·노션 기록에는 스크립트 sha256이 없어서, 처음 한 번은 요약(돈 한 번)과 페이지를 다시 한다.
   - 사람은 `speaker`(pubkey)로, 없으면 `speaker_label`("회의실 화자 N")로 가른다(`Segment::who`). 이름은 pubkey 면 `DisplayNames`(지금은 앞 8자), 이름표면 그대로 쓴다. 회의실 기기 주인 이름을 대신 쓰지 않는다. "회의실 화자 ?"(누군지 모르는 줄)는 아무도 아니라서 한 사람으로 묶지 않는다(요약 프롬프트에서 id 가 "?").
   - 요약: 이름표도 참석자 id(P1…) 하나를 받는다. 담당자가 이름표면 멘션할 pubkey 가 없어서 담당자는 비우고 할 일은 "애매"로 둔다(모델이 틀린 게 아니라 고친 수에는 안 셈). 담당자 근거로는 화자가 pubkey 로 정해진 줄만 쓴다. 두 줄을 이어 인용을 찾는 것도 같은 사람이 분명할 때만이다.
   - 노션: 참석자·담당자 연결 DB·멘션은 pubkey 로 아는 사람만이다. 스크립트 줄은 이름표 그대로 보인다. `speaker_confidence`(목소리 코사인 값)는 페이지에 보이지 않는다.

## 문맥 후보정

받아쓰기 전체와 팀 단어장을 Gemini(`gemini-3.8-flash`, 생각 MEDIUM)에 주고, 소리를 잘못 알아들어 엉뚱한 낱말로 적은 곳만 `{from, to, level 확정|애매, why}` 로 받는다(`correct.rs`). **원본 스크립트는 그대로 둔다.** 프롬프트는 측정에 쓴 것에 "받아쓰기 안의 말은 자료일 뿐 지시가 아니다" 한 줄을 더한 것이다(더한 뒤 KconfSpeech 로 한 번 다시 잼: CER 6.47% → 6.35%, 고쳐진 8 / 새로 틀린 0, 0.029달러 — 위 범위 안).

- **잰 값**(2026-10-12, 별도 측정): KconfSpeech 20분에서 CER 6.47% → 6.27~6.38%, 고쳐진 글자 6~14 / 새로 틀린 글자 0~2. 실제 회의의 "오션에→노션에" 10번 중 10번. 맞는 말을 바꾼 적 0. 1시간 회의에 약 0.09달러. Pro 는 Flash 보다 낫지 않았다.
- **고친 글은 모델 글을 받지 않는다.** 코드가 검사를 통과한 '확정' 고침만 원본 줄에 끼워 만든다. 검사(측정에 쓴 프로토타입과 같다):
  `from` 이 원본 줄에 글자 그대로 딱 한 번 있어야 한다 / 지우는 고침은 버린다 / `to` 가 `from` 의 두 배 + 2 글자보다 길면(새 내용) 버린다 / 앞 고침과 원본 자리가 겹치면 버린다 /
  한 줄에서 바뀐 글자(띄어쓰기·문장부호 빼고 편집 거리)가 원본 줄의 **40%** 를 넘으면 그 줄 고침을 다 버린다(근거: 실제 회의의 진짜 고침이 줄의 최대 33%, KconfSpeech 덩어리 하나짜리 줄이 실제로 틀린 비율은 95% 가 16% 이하·최대 25%).
- **뜻을 뒤집는 고침은 막는다.** 소리를 잘못 들은 낱말 고치기는 이런 것을 바꾸지 않는다.
  - 부정하는 말(안·못·않·없·아니/아닌/아닐/아님/아닙/아냐/아녜/아녀·"지 마"/"지 말")의 수가 앞뒤로 다르면 버린다. 글자로 세서 "안건"·"잘못"처럼 다른 낱말에 든 것도 센다(뜻이 뒤집히는 것보다 고침 하나 덜 하는 편이 낫다).
  - 띄어쓰기로 나눈 낱말 수가 바뀌면 버린다. 다만 띄어쓰기·문장부호 뺀 글자가 똑같으면(띄어쓰기만 고침, 예: "분 리"→"분리") 둔다. 소리와 띄어쓰기를 같이 고친 것("달라 줄"→"달라질")은 버리는 대가를 받아들인다.
  - 결정 낱말(취소·확정·보류·승인·거절·거부·반려·가능·불가·연기·중단·중지·결정·합의·동의·반대·찬성·완료)을 넣거나 빼면 '확정'이어도 '애매' 제안으로만 둔다.
  - 시각·날짜도 같다: 숫자(0~9), 요일(월요일~일요일), 오전·오후, 시·분, 그리고 한글 수사 뒤에 시·분·월·일·주·년이 붙은 꼴("세 시", "삼월", "열두 시")이 바뀌면 '애매'로만 둔다(수사 글자 하나만은 "세요"·"이번"·"오션"처럼 흔해서 안 센다).
  - `to` 가 원래 글자 수로도 `from` 의 두 배 + 2 를 넘거나, 제어·서식 문자(Cc·Cf)나 괄호가 있으면 버린다(노션의 "(원래: …)" 표시를 흉내 내지 못하게).
  - 잰 값(2026-10-12, 돈 안 듦): 측정한 Flash 여섯 번의 고침을 이 규칙으로 다시 매기면, 확정 고침 4~8개 중 1~3개가 글에 안 들어가고(부정 0~2: 사람 이름 안의 "안"·장소 "안에서" 처럼 부정 뜻이 아닌 것, 소리+띄어쓰기 1~2) CER 은 6.35~6.40%, 고쳐진 글자 5~8, 새로 틀림 0~1 이다(규칙 전 6.27~6.38%, 6~14, 0~2). 측정한 고침 중 시각·결정 규칙으로 '애매'가 된 것은 없다.
- **요약의 근거는 원본으로 검사한다.** 요약 모델은 고친 글을 읽지만, 근거 시각·담당자·기한 인용과 확정 판정은 원본 스크립트로 본다. 그래서 고친 글이 원본에 없는 약속을 만들어도 담당자·확정·멘션이 되지 않는다. 대신 고친 낱말이 든 인용은 원본에서 못 찾아서 담당자가 비고 '애매'가 될 수 있다.
- **'애매'는 글에 넣지 않는다.** 확정과 같이 넣어 봐서 살아남은 것만 노션에 "혹시 ○○?" 제안으로 보이고, 요약에는 안 들어간다.
- **결과 파일** `{첫 세션 id}.corrected.json`(`huddle-corrected/1`, 0600): `script_sha256`, `model`, `glossary`(단어장 판), `usage`(토큰·비용), `dropped`(검사에서 버린 수), `lines`(스크립트 `segments` 번호 → `{corrected, edits, status}`; 모델이 고침을 낸 줄만. `edits` 는 들어간 확정과 제안으로 남은 애매, `status` 는 `고침`·`제안`·`버림`). 쓸 때마다 고친 글은 `edits` 의 확정만으로 다시 만든다(`corrected` 글은 사람이 보라고 둔다).
- **단어장**: 저장소의 `crates/buzz-huddle-minutes/glossary.txt`(한 줄에 낱말 하나, `#` 은 설명). 바이너리에 같이 들어간다. 시작은 측정에 쓴 11개 그대로이고, 짐작으로 늘리지 않는다. 판은 낱말만의 sha256 앞 12자다. 판이 바뀌어도 옛 후보정은 다시 하지 않는다(기록만).
- **순서와 도장**: 스크립트 → 후보정 → 요약(확정만 들어간 글) → 노션.
  - 요약(`corrected_sha256`)과 노션 기록(`corrected_sha256`)에 어느 후보정으로 만들었는지 적는다. 원본 글로 만들었으면 비운다.
  - 후보정이 바뀌면(처음 생기거나 다른 것) 요약과 페이지를 다시 한다. 그래서 후보정을 나중에 켜면 녹음이 남은 옛 회의도 후보정 → 요약(돈 한 번 더) → 페이지를 다시 한다.
  - 후보정을 끄면 도장을 비교하지 않고 원본 글을 쓴다(이미 만든 것은 그대로).
- **회의록을 막지 않는다**: 후보정이 없으면(이 실행에서 꺼짐·기다림·실패·포기) 요약과 페이지는 원본 글로 간다. 나중에 후보정이 되면 그때 다시 만든다. 포기하면 원본 글 그대로 끝이다(요약을 다시 내지 않는다).
  후보정 뒤에 새로 내는 요약이 실패하는 동안 페이지는 기다린다(옛 페이지는 그대로). 끝내 포기되면 "요약 실패" 대신 같은 스크립트의 옛 요약(후보정 전 글로 만든 것)을 페이지에 쓴다. 요약 실패 기록은 스크립트마다 하나라, 후보정 전 글로 이미 포기된 요약은 후보정이 와도 다시 하지 않는다.
- **노션**: 전체 스크립트는 줄마다 고친 글에 줄 안 표시를 붙여 보인다. 고친 낱말은 "노션에(원래: 오션에)", 애매 제안은 "오션에(혹시 노션에?)". 블록 수는 후보정이 없을 때와 같다. 원본은 스크립트 파일에 그대로 있다.
- **로그**: 숫자만. `correct: fixed N suggested M dropped K | input … output … thinking … tokens …, … s | cost $…`.

## 실패 처리 (후보정·요약·노션)

후보정·요약·노션 페이지는 실패를 한 모양으로 다룬다. 후보정은 아래 표의 "요약" 줄을 그대로 따르고(같은 함수·같은 수), 기록은 `{첫 세션 id}.correct-failed.json` 이다. 다른 점은 둘이다. 답이 잘리면 짧게 다시 묻지 않고 바로 paid +1 이다. 포기하면 요약·페이지가 원본 글로 만들어지고 끝난다("요약 실패" 같은 표시는 없다).

- **기록 하나**: 회의마다, 단계마다 스크립트 옆에 실패 기록이 하나 있다. `{첫 세션 id}.summary-failed.json`, `{첫 세션 id}.notion-failed.json`(`huddle-step-failures/1`): `script_sha256`, `paid_tries`(돈 냈거나 냈을 수 있는 시도), `free_fails`(돈 안 든 실패), `uncounted_bad_requests`(회의 몫으로 안 센 400·404), `last_kind`·`last_code`(종류·코드, 회의 글 없음), `next_try_after_unix_ms`(이 시각 전엔 그 회의의 그 단계를 안 함). 다른 스크립트(sha 가 다름)의 기록은 없는 것으로 친다.
- **돈 냈을 수도 있음**: 200 을 받았다, 또는 요청을 다 보낸 뒤 시간이 다 됐거나 연결이 끊겼다(받지 못한 답에도 돈이 났을 수 있다). 이런 요청은 같은 실행에서 다시 안 보낸다.
- **물러서기**: 돈 안 든 실패 n 번째 뒤에는 10분 × 2^(n-1), 많아야 6시간을 기다린다(10·20·40·80·160·320분). 그동안 다른 회의는 그대로 한다.
- **400·404**: 설정이 틀렸을 수도 있어서, 같은 실행에서 다른 회의의 그 단계가 먼저 성공했을 때만 회의 몫(`free_fails`)으로 센다. 아니면 `uncounted_bad_requests` 로 따로 세고 물러서기만 한다. 서로 다른 회의에서 연달아 400·404 면 설정 신호로 보고 그 실행 동안 끄고, 둘째부터는 회의 몫으로 안 센다. 그래서 설정이 틀린 동안엔 하루가 지나도 아무 회의도 포기되지 않고, 고치면 다음 시도에서 저절로 된다.
- **실행 끄기**: 서비스 쪽 신호에만 한다. 인증·권한·429 는 바로, 일시 오류·시간초과·연결 끊김·토큰 출처 무응답은 서로 다른 회의에서 연달아 2번일 때, 400·404 도 연달아 2번일 때 끈다. 다른 종류의 결과가 오면 연달아 센 것을 0으로 돌린다. 끈 단계는 그 실행의 남은 회의에서 `next run (off for this run …)` 로 남고, 다음 실행은 다시 해 본다.
- **끝**: 요약은 돈 냈을 수도 있는 시도 3번이나 돈 안 든 실패 7번째(6번이 넘으면, 약 10시간 반), 또는 안 센 400·404 11번째(첫 번부터 약 34.5시간: 설정이 틀린 걸 알아채고 고칠 하루 반)에서 포기한다. 늘 맨 앞에 와서 앞에 성공이 없는 이상한 회의도 이렇게 결국 페이지를 받는다. 포기하면 노션 페이지 요약 자리에 "요약 실패"를 적어 쓰고 그 회의는 끝난다. 노션 페이지는 포기하지 않고 6시간마다 다시 해 본다(실패한 페이지는 "실패"로 표시되고, 못 하면 `notion-stale` 로 찾는다).

## 실행 (Cloud Run 작업)

`buzz-huddle-minutes process --all`을 10분마다 돌린다. 녹음 접두사 아래의 community/channel 폴더(UUID인 것만)를 스스로 찾아 채널마다 회의를 처리한다.
채널 하나를 못 읽어도 다음 채널은 계속하고, 인증·권한·한도 오류만 실행 전체를 멈춘다. 실패가 하나라도 있으면 0이 아닌 값으로 끝난다.
한 실행은 시간 상한(기본 50분)이 지나면 새 회의를 시작하지 않고 남은 것은 다음 실행에 넘긴다(lease 2시간보다 짧게).
실행이 10분을 넘기면 다음 실행과 겹친다. Cloud Run 작업은 이것을 막지 않으므로, 같은 회의는 lease로 한 실행만 처리한다.

**되돌리기 주의**: 화자 분리 머지부터 스크립트는 `huddle-transcript/2` 로 쓴다. 그 뒤에 5e756f1a3 이하(머지 전) 이미지로
되돌리면, 옛 작업기는 스크립트 목록을 읽을 때 스크립트 전체를 읽어서 `/2` 줄(`speaker: null` 등)을 못 읽고 그 채널이
멈춘다. 되돌릴 때는 이 머지 이상 이미지로 한다(지금 작업기는 목록에서 `session_ids` 만 읽어 어떤 형식이든 넘긴다).

## 스크립트 JSON `huddle-transcript/2`

```json
{
  "format": "huddle-transcript/2",
  "community_id": "…",
  "channel_id": "…",
  "parent_channel_id": "… 또는 null",
  "session_ids": ["…"],
  "started_at": "2026-10-12T05:00:00.000Z",
  "ended_at": "2026-10-12T05:42:10.120Z",
  "duration_ms": 2530120,
  "participants": [{ "pubkey": "hex", "speech_ms": 600000 }],
  "segments": [
    { "start_ms": 1200, "end_ms": 5400, "device": "hex", "speaker": "hex",
      "speaker_label": null, "speaker_confidence": 1.0, "text": "…" },
    { "start_ms": 6100, "end_ms": 9800, "device": "회의실 기기 hex", "speaker": "hex 또는 null",
      "speaker_label": "회의실 화자 1", "speaker_confidence": 0.71, "text": "…" }
  ],
  "audio": { "key": "… 섞은 오디오 경로", "expires_at": "… 녹음 만료 시각" },
  "stt": { "engine": "google-chirp_3", "region": "us", "language": "ko-KR", "billed_seconds": 0 },
  "losses": {
    "lost_chunks": 0, "missing_chunks": 0, "unreadable_chunks": 0, "unreadable_manifests": 0,
    "unreadable_sessions": 0, "dropped_frames": 0, "failed_segments": 0
  }
}
```

- `start_ms`·`end_ms`는 회의 시작(첫 세션 `started_at`)부터의 밀리초. 앱·노션에서 "글 누르면 그 시각부터 재생"에 그대로 쓴다.
- 줄마다 화자 칸 넷:
  - `device`: 그 소리가 실린 트랙(기기) pubkey.
  - `speaker`: **말한 사람의 pubkey. 어느 경우든 같은 사람은 같은 pubkey** 다(앱·노션은 같은 pubkey 를 같은
    사람으로 보여 준다). 모르면 `null`.
    - 자기 기기로 혼자 말한 트랙: 트랙 주인.
    - 회의실 트랙: 목소리로 맞춘 사람(같은 회의의 깨끗한 트랙 또는 저장된 목소리 프로필). **회의실 기기 주인이라고
      그 pubkey 를 저절로 주지 않는다** — 주인도 목소리로 맞춰야 한다.
  - `speaker_label`: 회의실 트랙에서 나뉜 화자의 이름표 "회의실 화자 N"(회의 전체에서 처음 말한 순서). 이름이
    맞춰져도 남는다(앱에서 "회의실 화자 1 = 이 사람" 이라고 고칠 때 쓴다). 혼자 쓰는 트랙은 `null`.
  - `speaker_confidence`: 자기 트랙 주인이면 1, 목소리로 맞췄으면 그 코사인 유사도, `speaker` 가 `null` 이면 `null`.
- `huddle-transcript/1`(화자 나누기 전) 스크립트도 그대로 읽힌다: `device` = `speaker`, 확실도 1, 이름표 없음.
- 이름(표시 이름)은 넣지 않는다. 앱과 노션 쓰기 단계에서 pubkey로 찾는다.
- `losses`는 이 회의에서 빠진 것으로 알려진 것의 개수다(0이 아니면 앱·노션에서 "일부 빠짐"을 보여 줄 수 있게).
  - `lost_chunks`: 녹음기가 올리지 못한 조각(manifest 값). 번호 빈 곳은 이것으로 세고 다시 세지 않는다.
  - `missing_chunks`: 있어야 하는데 저장소에 없는 조각(manifest에 있는데 없음, manifest가 없으면 0번부터 마지막 번호 사이 빈 곳).
  - `unreadable_chunks`: 있지만 못 읽은 조각. `unreadable_manifests`: 못 읽은 manifest(그 세션은 조각만으로 처리).
  - `unreadable_sessions`: 하나도 못 읽은 세션(쓴 시각으로 이 회의에 붙임). `dropped_frames`: 녹음기 큐가 넘쳐 버린 프레임.
  - `failed_segments`: "받아쓰기 실패"로 남은 덩어리 수.

## 화자 나누기와 누가 누군지

회의실에서는 마이크 하나만 켜고 여럿이 말하는 것이 기본이다(10/12 사용자). 그래서 트랙 하나 = 사람 한 명이 아니다.
코드는 `src/speakers.rs`(파이프라인에 끼우는 자리 하나), `src/diarize.rs`(B), `src/bleed.rs`(A), `src/voices.rs`(C).

1. **트랙 안 화자 나누기(B)**: 트랙마다 말 덩어리만 이어 붙여(쉼은 0.5초 무음으로 줄여) sherpa-onnx
   `OfflineSpeakerDiarization`(pyannote segmentation-3.0 + 목소리 특징 모델 + 군집)에 넣는다.
   - 화자 수는 모른다. 군집 문턱(`--cluster-threshold`)으로 정한다. 값과 까닭은 아래 "잰 값".
   - 말이 `--min-cluster-ms` 보다 적은 묶음은 버린다(헛기침·웃음이 새 사람이 되지 않게). 남은 화자가 둘 이상이면
     "여럿이 쓰는 트랙"이다.
   - **화자 토막**: 10ms 칸마다 가장 많이 덮은 화자를 매기고, 0.8초보다 짧게 끼어든 화자는 이웃에 붙이고, 토막
     경계는 ±0.2초 안에서 가장 조용한 곳으로 옮긴다. 토막은 목소리 특징과 새는 소리 검사에도 쓴다.
   - **cut(기본, A)**: 토막마다 받아쓰기에 보낸다. 자른 자리에는 앞뒤 여유를 붙이지 않는다(옆 사람 말이 섞여
     받아쓰기에 가지 않게). 화자가 하나뿐인 덩어리는 그대로라 장부 열쇠도 그대로다. 장부 열쇠에 토막 경계가 들어가서,
     화자 설정을 켜고 끌 때 경계가 바뀐 조각만 다시 보낸다.
   - **whole(C)**: 덩어리는 자르지 않고 단어 시각을 받아 줄을 나눈다. 단어마다 시각이 가장 많이 겹치는(없으면 가장
     가까운) 토막의 화자를 매기고, 같은 화자가 이어지는 단어끼리 한 줄로 묶는다(줄 시각은 그 단어들의 시각). 새어 든
     소리 토막의 단어는 버린다. 한 덩어리의 단어가 모두 한 화자면 글은 받아쓴 그대로 한 줄. 단어가 없으면(받아쓰기
     실패, 빈 결과) 덩어리에서 말이 가장 많은 화자에게 한 줄로 준다. 겹쳐 말한 곳에서는 한 문장이 두 줄로 나뉠 수 있다.
     조각 경계(장부 열쇠)는 VAD 덩어리 기준이라 화자 설정과 상관없다. 다만 단어 시각을 물으면 글이 달라져서, 같은
     설정이면 늘 같은 글이 나오도록 단어 시각을 묻는지가 바뀐 조각은 다시 보낸다: 화자 분리를 켜고 끌 때 여럿 트랙
     덩어리만 한 번씩(cut ↔ whole 을 바꿀 때도 같다).
   - **기본이 cut 인 까닭**(10/12 측정, 아래 "다른 방법과 견준 것"): KconfSpeech 실제 회의 발췌에서 A 가 CER 이 1%p
     낮고 화자는 같았다. 다만 그 자료에는 겹쳐 말하기가 없고, 겹침이 있는 가짜 회의실에서는 C 가 나았다. **실제 회의실
     겹침 녹음이 생기면 다시 재서 정한다.**
   - 말이 두 묶음 최소치보다 적은 트랙은 나눌 수가 없으니 화자 나누기를 돌리지 않는다.
2. **새는 소리(A, 가볍게)**: 남은 경우는 원격 참가자 소리가 회의실 스피커로 나와 회의실 마이크에 다시 잡히는 것
   (앱 에코 제거가 놓친 것). 덩어리마다 다른 트랙의 10ms 소리 크기 흐름과 상관을 잰다(다른 트랙이 0~400ms 먼저).
   상관 0.8 이상이고 다른 트랙이 3dB 이상 크면 받아쓰기에 보내지 않는다. 진짜 말 밑에 에코가 깔린 덩어리는
   상관이 낮아 남긴다(잘못 지우기보다 두 번 남는 쪽).
   - 하나 더: 회의실 화자 묶음이 목소리로 사람 P 에 맞았는데 P 가 같은 회의에 자기 기기로도 있고, 묶음의 말이
     P 자기 트랙의 말과 같은 시각(절반 이상)이면 같은 말이 두 번 잡힌 것이라 회의실 쪽 줄을 뺀다.
3. **누가 누군지(C)**: 회의실 화자 묶음마다 목소리 특징(긴 덩어리부터 60초까지 평균)을 내서,
   - 같은 회의에서 자기 기기로 혼자 말한 깨끗한 트랙(기본 켜짐),
   - 저장된 목소리 프로필(저장소를 줄 때)
   과 코사인 유사도로 견준다. 점수가 높은 짝부터 정하고, 사람 하나에는 묶음 하나만 준다(두 묶음이 같은 사람에
   맞으면 높은 쪽만). 문턱(`--naming-threshold`) 아래면 "회의실 화자 N" 으로 남는다.
   - 회의실 기기 주인에게 회의실 화자를 저절로 주지 않는다. 다만 **화자가 하나로 나온 트랙은 예전처럼 트랙
     주인**으로 본다(대부분의 트랙이 자기 기기라서). 주인의 준비된 프로필과 목소리가 다르면 회의실 트랙으로 돌린다.
     회의실 마이크에 한 사람만 말했거나, 화자 나누기가 여럿을 하나로 뭉쳤는데 주인 프로필이 없으면 그 말이 기기 주인
     이름으로 간다 — "알려진 한계".
   - 스크립트 줄과 화자 나누기 기록이 어긋난 회의실 트랙(`mismatched_tracks`, 0 이어야 한다)의 줄은 누구 것인지
     모르므로 `speaker` null, 이름표 "회의실 화자 ?" 로 쓴다(M1).
   - 한 줄에서 그 화자 몫이 절반 아래인 줄(다른 사람이 끼어들어 겹친 줄)은 이름표만 두고 `speaker`·확실도는 null(L7).
   - `participants` 는 실제 화자 기준이다(M3). 회의실 트랙 기기 주인의 말 시간은 0 에서 다시 세어 목소리로 그 사람에
     맞은 줄만 더하고, 회의실 마이크에서 목소리로 맞은 사람은 목록에 더한다. 누군지 모르는 회의실 줄은 아무에게도
     세지 않는다.

### 목소리 프로필 (회의 사이 저장)

사용자 결정(2026-10-12): "목소리 특징을 회의 사이에도 저장해. 법무 확인 다 했어." 검토 리뷰(H1~H4, M2·M5)와 재검토 반영.

> **지금은 프로필이 생기지 않는다 = 회의 사이 이름 맞추기는 사실상 꺼져 있다.**
> - 트랙에서 저절로 배우기(`--voices-learn`, `BUZZ_MINUTES_VOICES_LEARN`)는 **기본 끔**이다. 회의실 기기에서 남의 목소리가
>   주인 키에 쌓이는 문제(아래 "알려진 한계" 맨 위) 때문이다. 끄면 트랙으로는 프로필을 만들지도 고치지도 않고, 대기 재료도
>   쌓지 않고, `dissent` 도 쓰지 않는다. 저장소에 파일이 하나도 생기지 않는다.
> - 프로필은 **사람이 확인한 재료로만** 준비되게 할 생각인데, **그 길은 아직 없다.** 함수(`add_confirmed`)와 시험만 있고
>   명령줄·앱 길은 없다. 3단계 앱의 동의 화면 때 설계한다.
> - 그래서 지금 이름이 붙는 것은 **같은 회의의 깨끗한 트랙으로 맞추기**뿐이다(그건 그대로 켜져 있다). 저장소에 준비된
>   프로필이 있으면 맞추기·주인 검사는 그대로 동작한다.
> - 아래 대기·준비·`dissent`·재료 규칙은 배우기를 켰을 때 이야기다.

- **저장하는 것**: 목소리 특징 숫자(임베딩)와 메타데이터만. 원본 소리·잘라 낸 소리·**회의 id 는 저장하지 않는다.**
  ```json
  { "format": "huddle-voice-profile/2", "pubkey": "hex", "community": "커뮤니티 id",
    "model": { "name": "….onnx", "sha256": "…" },
    "created_on": "2026-10-12", "updated_on": "2026-10-12", "dissent": 0,
    "samples": [ { "source": "own-track 또는 confirmed", "seconds": 42.0, "day": "2026-10-12",
                   "embedding": [ … ] } ] }
  ```
  재료마다 남는 것은 출처 종류·말 길이(초)·날짜(일 단위)뿐이다. 사람이 확인한 재료에만
  `"confirmed_by": "확인한 사람 hex", "confirmed_on": "날짜"` 가 더 붙는다(L6, 자리만).
- **재료**: 자기 기기로 혼자 말한 깨끗한 트랙만(화자 나누기 결과 1명, 새어 든 소리 뺀 것, 특징 낸 말이
  20초 이상). 회의실에서 기계가 맞힌 화자는 재료로 쓰지 않는다(틀린 짝이 굳어진다).
- **대기와 준비(H1)**: 첫 재료 하나만으로는 쓰지 않는다 — 회의실 기기에 주인 아닌 사람이 혼자 말한 것일 수 있다.
  - 재료가 들어가도 서로 0.75 이상 닮은 자기 트랙 재료가 **둘 이상** 모일 때까지는 "대기"다. 대기 프로필은
    회의실 화자 맞추기에도, 주인 목소리 검사에도 쓰지 않는다.
  - "준비"가 되면 가장 큰 닮은 묶음(최근 5개까지)과 확인된 재료의 평균을 쓴다(말 길이로 무게). 처음에 남의 목소리가
    하나 섞여 있어도 묶음 밖이라 평균에 안 들어가고, 재료가 5개를 넘으면 오래된 것부터 빠진다.
  - 같은 회의를 다시 돌려 같은 재료(같은 출처·코사인 0.9999 이상)가 오면 넣지 않는다. 한 회의를 두 번
    돌려 "준비"가 되지 않는다(이 거르기의 한계는 "알려진 한계").
  - 준비된 프로필과 0.75 아래로 다른 깨끗한 트랙은 넣지 않고 `dissent`(반대 수)만 1 올린다. 재료가 들어가면 0 으로.
- **주인 목소리 검사와 그 위험(M2)**: 화자가 하나로 나온 트랙이라도 주인의 준비된 프로필과 0.75 아래로 다르면 회의실
  트랙으로 돌린다(그 트랙은 재료가 되지 않고, 주인 프로필 `dissent` 만 1 오른다). 프로필이 잘못 준비됐으면(예: 남의
  목소리가 두 번 들어감) 진짜 주인 트랙을 밀어낼 수 있다. 자동으로 고치지는 않는다 — 자동으로 바꾸면 회의실 노트북을
  자주 빌려 쓰는 사람 목소리로 주인 프로필이 넘어가는 같은 문제가 생긴다. 대신 `voices list` 에서 `dissent` 가 쌓인
  프로필을 보고 `voices forget` → (본인 동의 후) `voices allow` 로 처음부터 다시 모으게 한다.
- **사람이 확인한 이름표**(자리만 있음): 3단계 앱에서 "회의실 화자 1 = 이 사람" 이라고 고치면
  `VoiceConfirmation`(회의·기기·이름표·pubkey·확인한 사람·시각, 회의 id 는 요청 안에만) 형식으로 받아, 그 구간
  (`confirmed_spans`)의 녹음을 다시 풀어 특징을 내고 `add_confirmed` 로 `source: confirmed` 재료로 넣는다. 확인된
  재료가 하나라도 있으면 바로 "준비". 앱 연결은 나중에.
- **모델이 바뀌면**: 모델(sha256)이 다른 프로필은 맞추기에 쓰지 않고, 그 사람의 다음 깨끗한 트랙으로 새 모델 프로필을
  처음부터(대기부터) 다시 만든다.
- **위치(H4)**: 커뮤니티마다 따로 둔다. 맞추기 후보는 **그 회의 커뮤니티의 프로필만**이다.
  - 이름: `voices/{community_id}/{sha256(소문자 hex pubkey)}/{판 번호 10자리}.json`. pubkey 는 이름에 드러나지 않고 내용 안에만.
  - 로컬 폴더(시험용): `--voices-dir` / `BUZZ_MINUTES_VOICES_DIR`. 폴더 0700, 파일 0600, 임시 파일은 고유 이름.
  - GCS: `--voices-bucket <전용 버킷>` / `BUZZ_MINUTES_VOICES_BUCKET`(인증 `--voices-auth` / `BUZZ_MINUTES_VOICES_AUTH`).
    **회의록 버킷과 다른 전용 버킷**을 쓴다(아래 한계: 소프트 삭제).
  - 저장소를 주지 않으면 회의 사이 저장은 꺼진다(같은 회의 대조는 된다).
- **동시에 고칠 때(H2)**: 고칠 때마다 다음 판 번호로 **"없을 때만 쓰기"**(GCS `ifGenerationMatch=0`, 로컬은 하드 링크)로
  새 파일을 쓰고, 쓴 뒤 옛 판을 지운다. 두 워커가 같은 판을 쓰려 하면 하나만 되고, 진 쪽은 직전에 다시 읽어 한 번 더
  한다(또 지면 이번 회의는 넘어감, 보고 `raced`).
- **못 읽을 때(H2)**: 못 읽는 파일(깨진 JSON, 이름·내용이 안 맞는 것)은 건너뛰고 개수만 센다(`profiles_unreadable`).
  그 사람의 **가장 새 판**을 못 읽으면 그 사람은 고치지 않는다(못 읽는 것 위에 새로 쓰지 않는다). 목록 읽기 자체가
  실패한 회의는 프로필을 **읽지도 쓰지도 않는다** — 맞추기·주인 검사 없이 "회의실 화자 N" 으로만 쓴다.
  목록을 본 뒤 가장 새 판이 사라졌으면(그 사이 새 판이 써짐) "없음" 으로 보지 않고 처음부터 다시 읽는다(세 번까지,
  그래도 바뀌면 오류).
- **보기·지우기·다시 허락(H3)**:
  ```bash
  buzz-huddle-minutes voices list   --voices-bucket <전용 버킷>           # 커뮤니티·pubkey 앞 8자, 날짜, 분량, 대기/준비, 반대 수
  buzz-huddle-minutes voices forget <pubkey> --voices-bucket <전용 버킷>  # 모든 커뮤니티에서 그 사람 것을 지우고 다시 안 만든다
  buzz-huddle-minutes voices allow  <pubkey> --voices-bucket <전용 버킷>  # 본인이 다시 동의했을 때만. 다음 회의부터 새로 모은다
  ```
  - `forget` 은 먼저 "지운 사람" 표시(`voices/forgotten/{sha256(pubkey)}.json`, 내용은 `{"forgotten":true,"on":날짜}`)를
    쓰고, 그다음 모든 커뮤니티의 그 사람 폴더(`voices/{커뮤니티}/{열쇠}/`) 안 파일을 **판이 아닌 것(임시 파일 등)까지**
    모두 지운다. 하나 못 지워도 멈추지 않고 끝까지 돌고, 지운 수·못 지운 수를 알려 준다(못 지운 게 있으면 0 이 아닌
    값으로 끝나니 다시 돌린다).
  - **읽는 쪽도 표시를 본다**: 목록·읽기(`list`·`load`)는 표시가 있는 사람 파일을 남아 있어도 쓰지 않고 그 자리에서
    지운다(지우기가 중간에 실패했거나, 저장이 `forget` 과 겹쳐 되살아난 경우). 워커는 고치기 전에도 표시를 보고, 쓴
    뒤에도 다시 봐서 그 사이에 `forget` 이 돌았으면 방금 쓴 것을 지운다.
  - 표시는 `allow` 를 사람이 돌리기 전까지 남는다.
- **보유 기간(M5)**: 사람마다 커뮤니티마다 자기 트랙 재료 최근 5개(+ 확인된 재료). 날짜 말고는 기간으로 지우지 않고,
  `forget` 때까지 둔다. 옛 판은 새 판을 쓴 뒤 지운다.
- 로그·보고·`Debug` 에 특징 값을 찍지 않는다(`[192 numbers]` 처럼 개수만).

  `--minutes-bucket` 과 같이 쓰면 명령줄에서 거절하고, 실행에서도 한 번 더 막는다(환경 변수로는 켤 수 없다).

  길을 코드로 막은 것이다. 대역 엔진은 이름이 `placeholder` 라 받아쓰기 장부 설정 버전(엔진 이름이 들어감)이 달라서

### VAD 크기 맞춤 (`--vad-level`)

회의실 마이크에서 먼 사람 목소리는 작아서 VAD 가 놓친다. `--vad-level on`(`BUZZ_MINUTES_VAD_LEVEL=on`)이면 **VAD 가 보는
사본만** 크기를 맞춘다. 0.5초 창 RMS 를 −25dBFS 로 올리고(올리기만, 최대 +30dB), **−60dBFS 보다 조용한 창은 올리지 않는다**.
이득은 1초로 부드럽게 하되 1 아래로는 안 내려가게 하고(트랙 끝·짧은 대답이 작아지지 않게), ±1 로 자른다. 측정 담당 `build_agc.py` 에 바닥을 더한 식이고, 10ms 칸으로 계산해서 한 시간짜리
트랙도 사본 하나 말고는 메모리가 안 든다. **받아쓰기·화자 나누기·섞은 소리는 녹음 그대로**를 쓴다. 바뀌는 것은 덩어리
경계뿐이라 장부 열쇠 규칙(경계와 프레임)에 그대로 맞는다.

- **코드 기본은 끔, 배포는 켬을 권한다**(Cloud Run 작업 env `BUZZ_MINUTES_VAD_LEVEL=on`).
- **바닥 −60dBFS 를 정한 근거**(0.5초 창 RMS, 10/12):
  - 실제 허들 mixed 에서 말에서 0.5초 넘게 떨어진 창(1,253개)의 소리는 중앙 −60.1dBFS(25~75% 구간 −60.4~−59.8)다.
    앱의 잡음 지우기가 남긴 바닥으로 보인다.
  - KconfSpeech 먼 화자(−20dB 합성) 말 창은 하위 5% 가 −62.9dBFS(S000018)·−50.6dBFS(S000019), 중앙이 −52.4·−42.3 이다.
  - 그래서 잡음 바닥과 먼 말 아래쪽 사이인 −60 으로 잡았다. 아래 표에서 −65 와 거의 같고, −55 보다 먼 말을 더 잡는다.
- **VAD 만 돌려 잰 것**(Chirp 없음, 작업기 Rust VAD, 10/12). "정답 밖 초" 는 보낸 소리 가운데 KconfSpeech 정답 발화 구간 밖인
  초다. 정답 구간이 발화 wav 전체라 파일 안 쉼은 말로 친다.

  - 켬과 끔은 덩어리를 따로 잘라서 짝지은 비교가 아니다. 바닥 없는 먼 화자 숫자는 측정 담당 파이썬 값(10.23% → 6.41%)과 거의 같다.
  - 실제 허들은 정답 글이 없어 좋고 나쁨은 모른다. 덩어리가 길어지고(10 → 7) 잡힌 말은 70.4 → 73.9초다.

## 지킬 것

- 같은 덩어리에 돈을 두 번 내지 않는다(4번 "받아쓰기"의 장부). 회의마다 잠금이나 lease를 잡고, 장부를 열지 못하면 보내기 전에
  그 회의를 실패로 끝내고, 실행 횟수는 받아쓰기를 끝까지 돈 실행만 세고, 열쇠는 녹음된 Opus 바이트·자른 경계·설정 버전으로 만든다.
- 같은 회의를 두 번 처리하지 않는다. 이미 쓴 스크립트의 `session_ids`와 하나라도 겹치는 회의는 건너뛴다.
  워커 둘이 같은 회의를 동시에 잡지 않게 회의마다 잠금(`<첫 세션 id>.lock`, OS `flock` — 죽은 워커는 잠금을 남기지 않는다)을 잡는다.
  분 버킷을 쓸 때는 잠금 대신 lease 객체(`ledger/…/lease`, 만료 2시간)를 `ifGenerationMatch=0`으로 만든다.
  만료된 lease만 그 세대일 때 지우고(`ifGenerationMatch=<세대>`) 다시 만든다. 처리가 끝나면 자기 세대의 lease만 지운다.
  잠긴 회의는 건너뛰고 개수를 남긴다(`held by another worker`). 잠금을 잡은 뒤에 "이미 처리했나"를 다시 본다.
  가장 이른 세션이 14일을 넘은 회의는 건드리지 않는다(15일 삭제가 앞 세션부터 지우므로 반쪽 회의가 될 수 있음).
- 로그에 말 내용과 키를 남기지 않는다. 로그에는 pubkey 도 찍지 않는다(사람은 순번, 화자 단계는 숫자만).
  실행 보고의 회의실 화자 후보(`ClusterReport.scores`·`named`)는 이 회의에 없는 사람(저장된 프로필)도 담으므로
  pubkey 앞 8자만 둔다(L2).
- 실제 회의 스크립트·오디오를 저장소에 커밋하지 않는다(시험 결과는 `.cache/`).
- 받아쓰기에 실패한 덩어리는 빼지 말고 "받아쓰기 실패"로 남긴다(조용히 사라지지 않게).
  이미 받은 결과는 장부에 남겨 다시 보내지 않는다(4번 "받아쓰기"). 소리 거절은 바로 확정하고,
  일시 오류만 회의를 미룬다(회의마다 3번까지). 인증·권한·한도 오류는 그 회의와 남은 회의를 모두 멈추고 0이 아닌 값으로 끝낸다.
- 망가진 조각·manifest·세션 하나 때문에 다른 것을 버리지 않는다. 회의 하나가 실패해도 다른 회의는 계속 처리하고, 실패는 숫자로 남긴다.
- 스크립트·섞은 오디오·받아쓰기 장부는 0600, 그것들이 들어가는 로컬 폴더(`--out` 포함)는 새로 만들 때 0700으로 쓴다.
- 나이와 "조용함" 판단에 쓰는 지금 시각은 밖에서 넣는다(`process --now-ms`, 기본은 시스템 시각). 시험은 날짜에 기대지 않는다.

## 알려진 한계 (아직 안 고침)

- **트랙에서 저절로 배우기(`--voices-learn`)는 켜지 말 것** — 회의실 기기 반복 오염이 풀리기 전까지. 뿌리는 "그 기기의
  혼자 트랙 = 기기 주인" 가정이다. 회의실 기기에서는 주인 말고 다른 사람이 혼자 말하는 일이 늘 있고, 규칙을 덧대도
  막을 수 없어서 배우기를 끄고 기본값으로 뒀다. 켰을 때 생기는 일(재검토 시험, 소리 높이 대역, 2026-10-12):
  - 회의실 기기(주인 P1, 말 안 함)에서 같은 남 P0 이 서로 다른 회의 두 번 혼자 말하면 P1 프로필이 **P0 목소리로 "준비"**
    된다(재료 2개, 서로 닮음).
  - 그다음 회의실 회의(P0·P3, P1 없음)에서 **P0 줄 14개 중 10개가 P1 이름**으로 나간다.
  - 진짜 P1 이 자기 기기로 말하면 주인 목소리 검사에 걸려 **밀려난다**(P1 줄 2개 중 0개가 P1, 회의실 화자로 감).
  - P0 목소리가 P1 열쇠 아래 있어서 **`voices forget P0` 으로 지워지지 않는다**(P1 을 forget 해야 지워진다).
  - 같은 장면을 배우기 끈 채(기본) 돌리면: 프로필 0개, P0 줄 중 P1 이름 0개, 진짜 P1 줄 2개 중 2개가 P1.
  - **켜기 전에 막을 것**:
    - (a) 배우기를 켰다가 끄면 그동안 배운 프로필이 그대로 맞추기·주인 검사에 쓰인다(재검토: 끈 뒤에도 P0 줄 14개 중
      10개가 P1 이름). 끈 상태에서는 확인 재료가 있는 프로필만 쓰게 고친 뒤에 켠다.
    - (b) 실제 GCS 전용 버킷(소프트 삭제 0)에서 저장·목록·`forget`·`allow` 를 한 번씩 돌려 확인한다(지금은 로컬 폴더로만 시험함).
    - (c) 작업기 서비스 계정에 그 버킷 `voices/` 의 지우기 권한이 있어야 한다(옛 판 지우기, 지운 사람 남은 파일 지우기, `forget`).
    - (d) 파이프라인에서 화자 마무리(`speakers_stage.finish`, 프로필 고치기 포함)가 「일시 실패로 다음 실행에 다시」
      (`SttRetryLater`) 판단보다 먼저 돈다. 배우기를 켜면 다음 실행에 다시 할 회의에서도 프로필을 고친다. 그 판단 뒤로 옮기거나
      다시 할 회의에서는 프로필을 안 고치게 한 뒤에 켠다.
- 받아쓰기 장부 열쇠는 조각의 경계와 그 구간의 프레임이라, 열쇠가 같으면 보낸 소리도 같다. 화자 나누기(cut 은 경계를
  옮기고, whole 은 새는 소리뿐인 조각만 뺀다)·새는 소리 지우기·VAD 크기 맞춤은 경계만 바꾸고 보내는 소리는 그대로라 장부
  버전에 넣지 않는다: cut 이면 켜고 끌 때 경계가 바뀐 조각만, whole 이면 단어 시각을 묻는지가 바뀐 여럿 트랙 조각만
  다시 보낸다(장부의 결과가 단어 시각을 물은 것인지가 지금과 다르면 다시 보낸다).
  받아쓰기 앞에서 소리 자체를 바꾸는 처리(잡음 지우기·보내는 소리 크기 맞추기 등)를 넣으면 그 설정은 열쇠에 넣는다.
- whole 의 여럿 트랙 덩어리는 단어 시각을 켜고 받아서 그 덩어리 받아쓰기가 조금 나빠진다(위 4번, 같은 덩어리에서 CER
  +0.83%p). 끈 결과로 글을 쓰고 켠 결과로 시각만 맞추면 피할 수 있지만 그 덩어리 값을 두 번 낸다 — 아직 안 했다.
- whole 에서 겹쳐 말한 곳은 단어가 시각으로 두 화자에 번갈아 가서 한 문장이 여러 줄로 쪼개질 수 있다. 줄 시각은 그
  단어들의 시각이라 이웃 줄과 겹칠 수 있다(길이 0 인 줄은 만들지 않는다: 적어도 1ms, 덩어리 안).
- 단어 시각을 묻는 방식이 바뀐 조각(cut ↔ whole)은 장부에 있어도 다시 보낸다. 분 버킷 장부는 조각 객체를 처음 쓴 것만
  남기고 실행 끝의 묶음(`bundles/`)으로 새 결과를 남기므로, 바꾼 첫 실행이 받아쓰기 도중 인증·한도 오류로 멈추면 다시
  보낸 조각의 새 결과가 안 남아 다음 실행에 한 번 더 낸다(로컬 장부는 바로 남는다).
- 시험 대역(`TruthStt`)은 단어 시각을 문장 시간에 고르게 펴서 준다. 진짜 Chirp 단어 시각보다 거칠어서, 가짜 회의의
  "문장이 두 줄로 나뉨"(`sentences_split`)은 실제보다 많게 나올 수 있다.

- 세션이 겹칠 때 사람별로 앞 세션 마지막 프레임 시각 하나만 보고 뒤 세션 프레임을 버려서, 길게 겹치면 소리가 빠질 수 있다. 메시 주인 바뀜을 실측한 뒤 고친다.
- 시간 상한은 회의를 시작하기 전과 요약·노션을 시작하기 전(10분 남김)에 본다. 처리 중인 받아쓰기는 끝까지 하므로, 실행은 상한보다 회의 하나 처리 시간만큼 늦게 끝날 수 있다(Cloud Run 작업 제한 시간은 그만큼 여유 있게). Gemini 는 마감을 넘기는 요청·기다림을 안 해서 마감 안에 끝난다(예전 최악은 120초×4번 + `Retry-After` 360초×3번 = 26분이었다). 노션은 마감을 안 본다. 작업기에서 `Retry-After` 는 60초(+20%)까지만 따르지만, 페이지 하나에 요청이 많아서 한도에 계속 걸리면 마감을 넘길 수 있다.
- 채널의 스크립트 목록을 볼 때 스크립트(`{uuid}.json`)는 다 받는다(어느 세션이 처리됐는지 알려고). 스크립트가 많아지면 목록 파일을 따로 두는 게 낫다.
- 로컬 폴더 모드(`--out`)의 잠금·장부·스크립트는 그 기계 안에서만 보인다. Cloud Run처럼 실행마다 디스크가 사라지거나
  인스턴스가 여럿 도는 곳에서는 분 버킷(`--minutes-bucket`)을 쓴다.
- 잠금과 lease의 이름은 회의의 첫 세션 id다. 두 워커가 같은 때 회의를 다르게 묶으면(한쪽만 더 이른 세션을 봄) 서로 다른 잠금을 잡아
  같은 소리에 두 번 낼 수 있다. 회의가 10분 조용해진 뒤에만 처리하므로 드물다.
- 메모리: 사람 한 명이 1시간 머물면 약 1.15GB를 쓴다(회의는 이제 하나씩 받지만, 한 회의 안의 사람 소리는 통째로 든다). 실제 배포 전에 고친다.
- lease는 2시간이다. 한 회의 처리가 2시간을 넘기면 다른 워커가 넘겨받아 같은 덩어리에 다시 돈을 낼 수 있다(지금 회의 하나는 몇 분).
- 조각만 있는 세션의 끝은 마지막 조각 앞부분의 기록 시각으로 어림한다. 실제 끝보다 조각 하나(30초)만큼 짧을 수 있어서, 10분 간격 경계에 딱 걸친 세션은 회의가 갈릴 수 있다.
- Chirp 설정이 틀려 모든 요청이 400 `INVALID_ARGUMENT`로 오면, 덩어리마다 "소리 거절"로 확정돼 장부에 남는다. 설정 버전에는 엔진·지역·언어만 들어가서, 그 밖의 요청 설정(소리 형식 등)을 고쳐도 열쇠가 그대로다. 그때는 그 회의의 장부 객체를 정확한 이름으로 지우고 `--overwrite`로 다시 만들어야 한다.
- Join 기록보다 먼저 온 프레임은 누구 것인지 몰라 버린다.
- 늦게 온 프레임을 다시 줄 세우지 않는다(seq가 뒤로 가면 버림).
- 0.25초보다 짧은 대답("네")은 VAD에서 빠지고 따로 세지 않는다.
- **화자 나누기가 회의실 트랙을 한 명으로 뭉치면** 그 트랙 말이 모두 기기 주인 이름으로 간다(화자가 하나인 트랙은
  주인으로 보므로). 주인 프로필이 준비돼 있고 목소리가 다르면 "회의실 화자 1" 로 돌리지만, 프로필이 없거나 대기면 못 막는다.
  cal 에서 문턱을 높일수록 이 일이 생겨서(campplus 0.9: 회의실 16회의 중 2번) 문턱을 낮은 쪽(덜 뭉치는 쪽)으로 골랐다.
- **새는 소리 덩어리 검사(A)는 거의 일하지 않는다**: 회의실 덩어리는 길고 진짜 말과 에코가 섞여 있어 상관이 낮다.
  cal 16회의 에코 22개에서 지운 덩어리 0, 잘못 지운 진짜 말 0, 에코가 주인인 채 남은 줄 1. 받아쓰기 대역 기준으로는
  에코 문장 글이 두 번 나온 것이 11개(대역은 300ms만 겹쳐도 문장을 통째로 주므로 실제보다 나쁘게 센 값).
  실제 에코가 얼마나 남는지는 실제 회의 녹음으로 다시 잰다.
- 겹쳐 말한 곳은 10ms 칸마다 한 화자(가장 많이 덮은 쪽)에게만 간다. 0.8초보다 짧은 끼어들기("네")는 옆 화자 덩어리에 붙는다.
- 시뮬레이션의 한계: 낭독 말(Zeroth), 성긴 무작위 탭 울림, 앱의 소리 크기 조절·잡음 제거·에코 제거 없음.
  실제 회의실 녹음으로 다시 재야 한다.
- **목소리 프로필**:
  - 프로필 저장소를 회의록과 **같은 버킷**에 두면 `forget` 으로 지운 판이 버킷 소프트 삭제 기간만큼 남는다(회의록 버킷
    `gs://a2d2-huddle-minutes` 는 7일). 그래서 소프트 삭제 0 인 전용 버킷을 쓴다(`--voices-bucket`).
  - 이름의 `sha256(pubkey)` 에는 소금이 없다(L1). pubkey 는 공개 값이라 pubkey 를 아는 사람은 누구 파일인지 알 수 있다.
    이름은 버킷 목록에서 pubkey 를 바로 드러내지 않게 하는 것까지만 한다. 버킷 읽기 권한을 작업기 계정으로 좁힌다.
  - 잘못 준비된 프로필은 자동으로 고치지 않는다(M2, 위 "주인 목소리 검사와 그 위험"). `dissent` 를 보고 사람이 고친다.
  - 날짜는 일 단위라, 같은 날 같은 사람 재료가 몇 회의에서 왔는지는 남지 않는다(회의 id 를 남기지 않으므로).
  - 대기 프로필은 서로 닮은 재료가 하나 더 와야 쓴다. 자기 기기로 혼자 말한 회의가 한 번뿐인 사람은 회의실에서 이름이
    붙지 않는다.
  - **같은 재료 거르기(코사인 0.9999)**: 같은 출처 재료가 이만큼 닮으면 "같은 회의를 다시 돌린 것" 으로 보고 넣지 않는다.
    회의 id 를 남기지 않아서 이렇게 가린다. 서로 다른 회의 재료가 우연히 이만큼 닮으면 빠진다(재검토 시험의 소리 높이
    대역에서는 실제로 생겼다. 진짜 모델 cal 에서 같은 사람 깨끗한 재료 하나 대 나머지 평균은 34개 중 최고 0.975 였다). 반대로 설정(VAD·자르기)이
    바뀐 뒤 같은 회의를 다시 돌리면 특징이 달라져 두 번 들어갈 수 있다.
  - **사람이 확인한 재료(L6)**: 누가 확인할 수 있는지 권한 검사가 없고(`confirmed_by` 는 자리만 있다), 확인된 재료는
    오래돼도 빠지지 않고 `forget` 때까지 평균에 들어간다. 확인된 재료 하나로 바로 "준비"가 된다. 앱을 붙이기 전에
    누가 확인할 수 있는지(본인만? 커뮤니티 관리자?)와 확인된 재료를 언제 빼는지를 정해야 한다.
- **라이선스 표시**: 저장소에 NOTICE 파일이 없다. 작업기 이미지를 밖으로 내보내지 않으면 꼭 필요하지는 않고, 쓰는
  모델의 라이선스는 위 "모델" 표에 있다. 이미지를 밖에 낼 때 NOTICE 를 만든다.
- **빌드 때 받는 라이브러리**: `sherpa-onnx-sys` 의 build.rs 가 빌드할 때 GitHub 릴리스(`k2-fsa/sherpa-onnx`)에서
  미리 빌드된 라이브러리를 sha 확인 없이 받는다(이번 작업 전, Silero VAD 때부터 있던 것). 막으려면 확인한 파일을
  `SHERPA_ONNX_ARCHIVE_DIR` 또는 `SHERPA_ONNX_LIB_DIR` 로 준다.

## 아직 정할 것

- **노션 쓰기**: 노션 내부 통합 토큰(`a2d2-buzz-notion-token`)이 있어야 한다.
- **회의 끝 판단**: 부모 채널의 48103·채널 보관과 묶을지.
